### 발송 일정

| 언제 | 무엇 | 카톡 |
|---|---|---|
| **평일 오전 7시** | 아침 브리핑 — 전일 시장·ETF | 1건 |
| **목요일 오전 10시** | ETF 뉴스·출연자 추천 — 뉴스 6선 · 전문가 발언 · 출연자 추천 | 1건 |
| **토요일 오전 7시** | 주간 브리핑 — 주 단위 수급·자금흐름·구조 변화 | 1건 |

평일 브리핑에는 **전일 데이터만** 담습니다.
주 단위로 봐야 하는 지표는 토요일로, 출연자 전달용 자료는 목요일로 분리했습니다.

### 목요일 전달문

ETF 처방전 출연자에게 매주 목요일 전달하는 자료입니다.
화요일 00시부터 목요일 오전까지 보도된 기사를 모아 만듭니다.

- **ETF 뉴스 6선** — 주제가 겹치지 않게 분산(수급/신규상장/규제/해외동향/상품구조/시장규모) + 카톡 붙여넣기용 복사 텍스트
- **애널리스트·전문가 발언** — 실명으로 인용된 ETF·자산배분 발언만. 익명 코멘트는 제외
- **출연자 추천** — 발언 근거가 있는 인물만, 코너별로. 왜 지금인지 + 물어볼 질문까지

환각을 막기 위해 **수집된 기사에 실제로 있는 URL이 아니면 코드에서 제외**하고,
발언 근거가 없는 인물의 출연자 추천도 자동으로 걸러냅니다.

## 설계 원칙

**사실과 해석을 분리합니다.**

- 회색 `사실` 태그 = 검증 가능한 수치·발표 내용
- 보라색 `해석` 박스 = 데이터에 대해 가능한 설명 중 하나. "~가능성이 있습니다" 어미로 통일하고 반대 가능성을 함께 적습니다.
- 투자 권유로 읽힐 문장은 코드 레벨에서 차단합니다 (`src/llm.py`의 `BANNED`)

**한 이슈는 딱 한 번만 자세히 설명합니다.**

TOP 5에는 이슈명·숫자·ETF 영향 한 줄만 담고, 상세 해설은 '핵심 이슈'에서 한 번만 합니다.
같은 내용을 여러 섹션에서 반복하지 않습니다.

**개별 종목은 기본적으로 싣지 않습니다.**

"등락률이 컸다"는 이유만으로는 등장시키지 않습니다.
그 종목의 움직임이 지수나 ETF의 움직임을 설명하는 데 꼭 필요할 때만,
해당 이슈 카드 안에서 언급합니다. 브리핑 전체에서 최대 3종목입니다.
후보 종목은 `src/krx.py`가 매일 스크리닝하지만, 실제로 실을지는 AI가 판단합니다.

**의미 없는 날은 섹션 자체가 사라집니다.** '해당 없음', '특이사항 없음' 같은 문구는
코드 레벨에서 걸러냅니다 (`src/llm.py`의 `FILLER`).

**각 사실에 출처 링크가 붙습니다.** 어떤 숫자가 어느 기사에서 나왔는지
카드마다 확인할 수 있어야 질문지·대본에 그대로 쓸 수 있기 때문입니다.

**시점을 섞지 않습니다.** 레벨·등락폭·등락률은 반드시 같은 봉에서 계산하고,
각 지표에 `기준일`과 `상태`(마감/장중/스냅샷)를 붙입니다.
'시장 한눈에'의 그룹 라벨에 그 시점이 표시되며, 한 그룹 안에서 기준일이 섞이면
항목마다 날짜를 개별 표기합니다 (`src/market.py`, `src/render.py`).

**항상 최신 근거만 씁니다.** 근거 기사가 48시간을 넘긴 ETF 레이더 항목은
코드에서 제외합니다. "어제 이런 일이 있었다"고 썼는데 사흘 전 기사인 경우를 막습니다
(`src/llm.py`의 `STALE_HOURS`).

**국채 금리 변화는 bp로 통일합니다.** 수준은 %, 변화는 bp. 1bp = 0.01%p.

## 구조

```
config.yaml                 설정 (이 파일만 고치면 됩니다)
src/
  main.py                   진입점
  krx.py                    국내 시세·수급·ETF (pykrx)
  market.py                 글로벌 지수·원자재·금리 (yfinance)
  us_etf.py                 미국 상장 ETF 전 종목 흐름판 (NASDAQ)
  news.py                   뉴스 RSS
  youtube.py                YouTube Data API
  llm.py                    Gemini 요약·해석 생성
  render.py                 HTML 렌더링
  delivery.py               발행 채널 경계 (개인 Kakao → 회사 Slack 교체 지점)
  kakao.py                  카카오 발송 + 토큰 자동 갱신
templates/
  brief.html.j2             평일·주간 브리핑 템플릿
  handoff.html.j2           목요일 전달문 템플릿
docs/                       GitHub Pages 출력 (자동 생성)
.github/workflows/
  daily.yml                 매일 07:00 KST
  thursday.yml              목요일 11:00 KST (전달문)
  weekly.yml                토요일 07:00 KST
  setup-token.yml           카카오 토큰 발급 도우미 (최초 1회)
```

자동·수동 실행과 외부 스케줄러 운영 규칙은 **[OPERATIONS.md](OPERATIONS.md)** 에서
한 문서로 관리합니다.

## 직접 실행

```bash
pip install -r requirements.txt

# 데이터 수집 + HTML만 (AI·카톡 없음)
python -m src.main --dry-run

# AI까지 돌리되 카톡은 안 보냄
python -m src.main --no-send

# 전체 실행
python -m src.main

# 목요일 전달문
python -m src.main --mode thursday --no-send

# 토요일 주간 브리핑
python -m src.main --mode weekly --no-send
```
